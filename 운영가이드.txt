 0. 기본 개념 — 3분이면 이해 끝
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

● Supabase = 사장님의 "중앙 창고 겸 회원 관리소"
  - 고객 데이터, 라이선스 키 장부, 버전 게시판이 다 여기 있습니다.

● SQL = 창고 관리인에게 주는 "명령 쪽지"
  - 정해진 문장을 복사해서 숫자/글자만 바꿔 실행하면 됩니다.
  - 딱 3종류만 알면 됩니다:
     select  = "보여줘"       (재고·목록 확인)
     insert / generate = "만들어" (키 생산)
     update  = "바꿔줘"       (버전 알림, 키 정지 등)

● SQL 실행하는 곳 (항상 같습니다)
  1) supabase.com 로그인 → 내 프로젝트(Doodle) 클릭
  2) 왼쪽 메뉴에서 "SQL Editor" 클릭
  3) "New query" 클릭 → 명령 붙여넣기 → 오른쪽 아래 초록색 "Run" 클릭
     (또는 키보드 Ctrl + Enter)
  4) 아래 Results 칸에 결과가 나옵니다.

★ 명령 하나 실행 후 다음 명령을 하려면:
   입력칸을 클릭 → Ctrl+A (전체선택) → Delete → 새 명령 붙여넣기 → Run

 1. 라이선스 키 (판매의 핵심)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▶ 키 새로 발급하기 (괄호 숫자 = 개수)
  select public.generate_licenses(10);
  → DDB-XXXX-XXXX-XXXX-XXXX 형식 키 10개가 나옵니다.
  → 미리 넉넉히 만들어두고 판매할 때 하나씩 고객에게 주면 됩니다.

▶ 전체 키 목록 보기 (누가 어떤 키를 쓰는지 한눈에)
  select license_key, status, email, activated_at
  from licenses order by created_at desc;
  → status 읽는 법:
     unused  = 아직 아무도 안 씀 (= 팔 수 있는 키)
     active  = 어떤 고객이 사용 중 (email 칸에 그 고객 표시)
     revoked = 정지된 키 (환불 등)

▶ 안 팔린(unused) 키만 보기 — 재고 확인용
  select license_key from licenses where status = 'unused';

▶ 남은 재고 개수만 세기
  select count(*) from licenses where status = 'unused';

▶ 환불 처리 — 키 정지시키기 (XXXX 부분을 실제 키로)
  update licenses set status = 'revoked'
  where license_key = 'DDB-XXXX-XXXX-XXXX-XXXX';
  → 이 키를 쓰던 고객은 즉시 동기화가 막힙니다.

▶ 정지한 키를 다시 살리기 (실수로 정지했을 때)
  update licenses set status = 'active'
  where license_key = 'DDB-XXXX-XXXX-XXXX-XXXX';

 2. 업데이트 알림 (새 버전 냈을 때)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

새 버전 설치파일을 만들고 어딘가에 올린 뒤, 이 한 줄만 실행하면
전 세계 모든 유저에게 "새 버전 나왔어요" 알림이 뜹니다.

▶ 새 버전 알림 게시하기
  update app_meta set
    latest_version = '0.91.0',
    download_url   = '여기에 다운로드 주소',
    notes = '- 새로 추가된 기능
- 고친 점'
  where id = 1;

  ※ latest_version 은 반드시 지금 배포한 버전보다 높게!
    (예: 0.90.0 → 0.91.0 → 0.92.0 ...)
  ※ 작은 수정은 뒷자리(0.90.0 → 0.90.1),
    큰 기능 추가는 가운데 자리(0.90.0 → 0.91.0) 올리는 게 보통입니다.

▶ 지금 게시된 버전 확인하기
  select * from app_meta;

 3. 고객·회원 관리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▶ 전체 회원 수 확인
  select count(*) from auth.users;

▶ 최근 가입한 회원 보기
  select email, created_at, last_sign_in_at
  from auth.users order by created_at desc limit 20;

▶ 베타테스터에게 라이선스 무료로 붙여주기
  (친구 이메일로 계정을 먼저 만든 뒤 실행. 이메일 2군데 다 바꾸기)
  update licenses set status='active',
    user_id=(select id from auth.users where email='친구이메일@example.com'),
    email='친구이메일@example.com', activated_at=now()
  where license_key='DDB-발급한키' and status='unused';

  ※ 친구 계정 만드는 법: 왼쪽 메뉴 Authentication → Users
     → 오른쪽 위 "Add user" → "Create new user"
     → 이메일/비밀번호 입력 (이 방법은 인증 메일 없이 바로 생성됨)

 4. 용량·비용 관리 (무료 한도 지키기)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Supabase 무료 플랜: 데이터베이스 약 500MB.
넘으면 Pro 플랜(월 $25)으로 올려야 합니다.

▶ 데이터 많이 쓰는 고객 순서로 보기 (단위: KB)
  select user_id, pg_column_size(data)/1024 as kb
  from user_data order by kb desc limit 20;
  → 특정 고객이 유난히 크면 배경 이미지를 많이 넣은 것.
    (앱에서 이미 1MB로 제한해뒀지만 참고용)

▶ 전체 사용량 확인은 SQL 말고 화면에서:
  왼쪽 메뉴 맨 아래 Settings → Usage 에서 그래프로 볼 수 있습니다.

※ 무료 플랜 주의: 프로젝트를 1주일간 아무도 안 쓰면 "일시정지"될 수
  있습니다. 판매 시작 전이라 손님이 없을 때는, 가끔 로그인해서
  깨워주거나 Pro로 올리면 됩니다.

 5. 새 버전을 낼 때 전체 순서 (외워두면 편해요)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1) (수정 요청) → 새 dist 를 받아 작업폴더의 dist 에 덮어쓰기
  2) electron-app 폴더의 build-installer.bat 실행 → 새 설치파일 생성
     (이때 버전 번호를 올려둘 것: package.json 의 version)
  3) 새 설치파일을 판매처/드라이브에 업로드 → 다운로드 주소 확보
  4) SQL 실행 (위 "2번 업데이트 알림" 명령 한 줄)
  5) 끝! 유저들이 앱 켤 때 알림을 받습니다.

 6. 사고·문의 대응 (자주 나올 상황)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q. 고객이 "동기화가 안 돼요"
  → licenses 표에서 그 고객 이메일의 status 확인.
    unused/없음이면 키가 활성화 안 된 것 → 키를 제대로 입력했는지,
    이메일 인증을 마쳤는지 확인 요청.

Q. 고객이 "비밀번호를 잊었어요"
  → 로그인 창에 비밀번호 재설정 기능이 있으면 그것으로 안내.
    (없으면 향후 추가 가능)

Q. 고객이 "회원 탈퇴/데이터 삭제 해주세요"
  → Authentication → Users → 해당 이메일 → ⋯ → Delete user.
    (user_data 도 함께 자동 삭제됨)

Q. 키를 잘못 발급했거나 테스트 키를 지우고 싶다
  → delete from licenses where license_key='DDB-XXXX...';
    (단, 이미 active 인 키는 지우지 말 것. 정지는 revoked 로.)

 7. 절대 하면 안 되는 것 ⚠
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

× service_role 키를 앱이나 남에게 노출하기
   (이건 마스터키입니다. 앱에는 anon 키만 들어갑니다.)
× "drop table" 명령 실행 (표 자체를 통째로 삭제 = 데이터 증발)
× RLS(보안규칙)를 끄기 → 끄면 아무나 데이터를 볼 수 있게 됨
× where 없이 update/delete 실행
   (예: delete from user_data;  ← 전체 삭제됨! 반드시 where 조건 붙이기)

 8. 자주 여는 화면 위치 (Supabase 왼쪽 메뉴)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
